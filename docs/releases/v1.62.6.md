# Stratum v1.62.6

Hotfix release, so a patch bump under `contracts/RELEASE.md` §1.2.
The versionCode is derived from the first-parent commit count of the
build checkout, as since STR-205. Source is this release's own PR:
the fix and the release prep ship together.

## Fixes

- The app no longer crashes on open when a stored program contains a
  set with `rest_seconds = 0` (STR-248, this PR). STR-168 added a
  `require(restSeconds > 0)` guardrail to `LiftSet`; zero is a
  legitimate stored state meaning "no rest prescribed" (drop-set
  steps, legacy rows, imported templates), so `readProgram` threw
  `IllegalArgumentException` during hydration and the app
  crash-looped before rendering anything. The stored data was never
  at risk — the read failed, not the data. The invariant is now
  non-negative and the property documents the zero semantics;
  consumers (duration estimate, rest timer, overlays) already treated
  0 as no rest, so no consumer changes were needed.
- Regression coverage at three levels: the guardrail test now accepts
  zero rest and rejects negative rest; a mapper test hydrates a
  zero-rest entity; and a repository test seeds the raw legacy rows
  through the DAOs and reads the program back — that test fails on
  the pre-fix code with the exact production exception. The gap this
  closes: the old guardrail test pinned the throw at 0 as intended
  behavior, and no read-path fixture ever seeded a value the database
  can legitimately hold but the constructor rejected.
