# Stratum v1.62.7

Hotfix release, so a patch bump under `contracts/RELEASE.md` §1.2.
The versionCode is derived from the first-parent commit count of the
build checkout, as since STR-205. Source is this release's own PR:
the fix and the release prep ship together.

## Fixes

- Some workouts no longer fail to start (STR-250, this PR). The Ab
  Roller catalog row was typed Weighted while its equipment is
  Bodyweight: the seed declared no loadType, so the seeder defaulted
  it to Weighted. Performed bodyweight, every logged set is 0 lb, and
  at workout start the progression snapshot derived an estimated 1RM
  of 0 from that history and fed it into
  `EstimatedOneRm.repsForWeight`, which throws
  `IllegalArgumentException: estimatedOneRm must be positive`. The
  session actor went terminal and the workout landed on an error
  screen. Three layers fixed:
  - The save path: the domain now owns the load-type/equipment
    alignment invariant (a lift on Bodyweight equipment must be
    Bodyweight; a Bodyweight lift cannot carry loaded equipment), and
    the seeder enforces it at import — a contradictory row fails the
    seed loudly instead of persisting. A validation test runs the
    real bundled catalog through the real mapping path; it flagged
    30 rows, and the data is fixed for each (see the PR description
    for the per-row adjudication). Ab Roller now seeds as Bodyweight.
  - The snapshot math: a zero-load history set carries no load
    information, so tightening, the partial-tail anchor, and baseline
    reprojection now skip a baseline whose estimated 1RM is not
    positive and leave the candidate weight unchanged for that step,
    instead of throwing. The `EstimatedOneRm` invariant itself is
    unchanged.
  - The skips are not silent: each one is recorded as a domain
    diagnostic value, returned with the snapshot, and logged exactly
    once by the session actor through its existing error-logging
    wiring. Diagnostics are log-only; nothing new surfaces in the UI.
- Existing installs: catalog seeding runs only on first install (or
  after an account data clear), and seed rows the user has edited
  cannot be distinguished safely enough to rewrite them in place, so
  this release does not rewrite stored catalog rows. The snapshot
  guard unblocks affected workouts regardless; flipping the lift's
  type in Lift Details corrects the row itself. Fresh installs and
  data-clear reseeds get the corrected catalog. See the PR
  description for the full rationale.
- Regression coverage: a domain test reproduces the production stack
  (it fails on pre-fix code with the exact production exception and
  frames), plus a partial-tail anchor case; seed tests assert the
  whole bundled catalog satisfies the invariant, that Ab Roller
  seeds as Bodyweight, and that a contradictory row throws at
  mapping; a feature test drives a session start on zero-load
  history and asserts each skipped baseline reaches the logging port
  exactly once.
