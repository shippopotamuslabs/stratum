# Stratum v1.62.5

Fixes only, so a patch bump under `contracts/RELEASE.md` §1.2. The
versionCode is derived from the first-parent commit count of the build
checkout, as since STR-205. There is still no release tag (the first
one is cut by this release's deploy), so the source set for these
notes is the work merged since the v1.62.4 release prep (PR #32):
PRs #33 through #40.

## Fixes

- Save as New keeps unique equipment names (STR-246, PR #36). The
  shared fork-name policy numbered every copy starting at 2; it now
  passes a unique name through unchanged and numbers collisions from
  (1). Both fork flows, proposal ranking, and the import stack clone
  share the corrected policy.
- A mid-session equipment delete with a replacement assigned now
  re-derives the whole session from the replacement (STR-235,
  PR #37). The session snapshot's structure fingerprint includes the
  resolved equipment per slot, so a delete sweep rebuilds the snapshot
  onto the replacement's increments instead of leaving the session
  half-swapped. Logged history is never rewritten.
- Workout auto-scroll lands the focused lift card's top edge on the
  pin line under the lift timeline (STR-233, PR #38). The landing
  math was in the wrong coordinate space and stopped one
  top-content-padding short on every scroll; a settle pass now also
  corrects for layout shifting mid-animation. Timeline taps and
  superset focus transitions take the same path.
- The first working set after a completed rep-match mini-set cluster
  builds off the match top set (STR-232, PR #39). The block
  re-roots at the activation and the backoff plus its cluster count
  as one normal fatigue step, so the set takes the normal per-lift
  fatigue gradient instead of collapsing to the rep floor at a
  reduced weight. RepFloor blocks are unchanged by design: their
  minis parent to the activation itself.
- A fresh sign-in after an Auto Backup restore converges to the
  server (STR-206, PR #40). The sync state file (account owner,
  hydrate flags, pull cursors) is excluded from cloud backup and
  device transfer, so a restore boots with blank sync state: restored
  local rows are wiped before the first upload and the first sign-in
  full-pulls. The push path was audited in the same ticket: uploads
  already last-write-wins on the business `updated_at_epoch_millis`,
  never on client write time, tombstones included.

## Internal

- Lift and Equipment behavior centralized on the domain models
  (STR-169, PR #34) and Entitlement, profile, and onboarding-progress
  rules likewise (STR-170, PR #35). Rich-domain chunks of STR-163;
  no behavior change.

  notes; it is listed in Source because it merged in this range.
