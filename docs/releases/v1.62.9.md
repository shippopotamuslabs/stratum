# Stratum v1.62.9

Patch bump under `contracts/RELEASE.md` §1.2: the range since the
v1.62.8 tag carries two user-visible fixes and a body of internal
work, and adds nothing new a user can see or use. The versionCode is
derived from the first-parent commit count of the build checkout, as
since STR-205.

## What changed

- STR-264 (PR #68) fixed the Recovery dashboard Sleep total. The
  total was the full sleep-session span, time in bed, so a night with
  8h 1m in bed and 14m awake showed 8h 1m of sleep. The rule now
  lives on the domain models: `SleepZones.asleepWithin(span)`
  subtracts the awake bucket, and `NightlySleepDuration` and
  `SleepNight` take the span as input and expose `duration` as a
  computed property. The Sleep card, the 7-day average, last night,
  and the plain nightly bars all read that duration. Sessions with
  no stage data keep the span, because there is no awake time to
  subtract.
- PR #52 gave text fields in bottom sheets a contrasting border.
- The diagnostics-as-values program (doctrine codified in STR-251,
  PR #53; gospel §10) rolled through the app: slot drops in program
  generation (STR-254), lift merge and swap degradations (STR-255),
  compensating-action failures on auth and import outcomes
  (STR-256), Health Connect metrics-load and permission degradations
  (STR-257), the program schedule fallback (STR-258), analysis and
  history failures (STR-259), program-change-event skips routed
  through LoggingPort (STR-260), and Play sync failures in the data
  layer (STR-262). Partial failures now travel inside the result
  values to the logging layer instead of being logged at the site.
- STR-242 (PRs #55–#57) added the telemetry router and outcome
  emission, routed exceptional failures with a bare occurrence
  counter, and published the Grafana dashboards and phase-1 alerts.
- The Health Connect boundary purification (STR-265 audit children)
  landed: STR-266 (PR #72) split the failure taxonomy at the sync
  port so vendor states and the WorkManager terminal/retryable
  policy no longer share one type; STR-267 (PR #73) reframed the
  domain metrics model agnostically and cut the sleep-stage model
  to the stages the domain math actually distinguishes
  (Light/Deep/Rem/Awake), with the mapper completing SDK
  translation; STR-268 (PR #74) purified the boundary values, so
  the snapshot diagnostic no longer carries the raw adapter
  Throwable and the persisted pending-sync error is now a closed
  HealthFailureKind enum (Unavailable/PermissionDenied/Unknown)
  persisted by name, with the UI wording the kinds itself and
  legacy free-text values defaulting to Unknown. STR-263 (PR #70)
  also landed in this range: Health Connect preference write
  failures return as results instead of being logged inside the
  repository.
- The infrastructure fold (STR-228) completed in this range.
  `:core:inference` and `:core:data` both folded into the new
  `:core:infrastructure` module, in chunks: the module created and
  `:core:inference` folded in (STR-269, PR #75); persistence —
  database, mappers and Room schemas, with the seed package and the
  `SyncFlags` constants pulled in early so the DAO SQL templates
  compile in-module (STR-270, PR #77); repositories, the preference
  stores and the sync write-coordination layer (STR-271, PR #78);
  Health Connect, auth, subscription, feature flags and telemetry
  (STR-272, PR #80); the Firestore sync transport (STR-274,
  PR #81); the Hilt DI modules, the last code left in `:core:data`,
  after which the empty module was deleted and the mapper surface
  the moves had to widen went back to `internal` (STR-275,
  PR #82); and the ARCHITECTURE.md module map redrawn to name the
  module that exists (STR-276, PR #83). STR-273 needed no PR of
  its own: its seed scope landed in PR #77 and its
  preference-store and workout scope in PR #78. The fold changed
  no behavior; it moved code between modules and restored the
  visibilities the moves had widened.
- Repo plumbing in range: Forge v2.0.0 and Chomp pinned (FRG-30,
  PR #51), the Chomp caller pointed at the renamed reviewer repo
  (CHOMP-56, PR #62), the gospels pin bumped for §11 canon (GLO-33,
  PR #54), the local plans directory ignored (PR #59), and the
  OSV scan reworked so a PR fails only on vulnerabilities it
  introduces, with the full scan running nightly on main
  (STR-277, PR #79).

## Behavior changes

- Sleep totals drop to time asleep wherever awake stage data exists.
  The staged stacked bar is unchanged: awake stays its own labeled
  segment there, per STR-98.
- Bottom-sheet text fields show a contrasting border.
- The diagnostics and telemetry work changes how failures are
  reported internally. Outcomes for the user are unchanged.
