# Stratum v1.62.8

Internal architecture release, so a patch bump under
`contracts/RELEASE.md` §1.2: the range since the v1.62.7 tag adds
nothing a user can see or use. The versionCode is derived from the
first-parent commit count of the build checkout, as since STR-205.
This release ships the completed STR-163 rich-domain-model program to
a real device so the new module structure gets smoke-tested before
feature work builds on it.

## What changed

- STR-172 (PR #46) extracted `:core:application`. All use cases and
  the outbound ports they consume moved out of `:core:domain` into a
  new JVM module under `com.stratum.application.<area>`; their tests
  moved with them. `:core:domain` keeps the models, value objects,
  and domain services/engines. The module edge is compiler-enforced:
  a probe file importing an application type from domain fails
  `:core:domain` compilation. Local gates before the PR: 8,593 domain
  tests and 958 application tests green (9,551 combined, reconciling
  with the pre-split suite), detekt clean, app assembles. The PR ran
  770 files because a module split is atomic — intermediate states do
  not compile — and Forge could not review it (GitHub returns HTTP
  406 for the diff at that size; the reviewer-side fix shipped
  separately as forge-reviewer v1.1.7, FRG-53). Sean admin-merged the
  PR with every required CI check green and the local evidence above
  on the ticket.
- STR-171 (PR #45) closed the architecture violation the program
  found on its way: EditWorkoutViewModel injected a repository
  directly, behind a leftover detekt suppression. It now routes both
  program-change event appends through
  `AppendProgramChangeEventUseCase`, and the suppression is gone.
- STR-200 (PR #49) rewrote the README Architecture section and
  module table to the finalized shape, so the repo describes the
  structure the code now has.

## Behavior changes

None intended. This release is the same app on a new internal
structure; the device build exists to prove that on hardware.
