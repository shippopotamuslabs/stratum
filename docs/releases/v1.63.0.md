# Stratum v1.63.0

Minor bump under `contracts/RELEASE.md` §1.2: the range since
v1.62.10 carries one user-visible behavior change (health metrics
render as unavailable when their read fails) on top of the STR-236
error-handling rebuild, which reworks how failures move through
every layer of the app. The versionCode is derived from the
first-parent commit count of the build checkout, as since STR-205.

## What changed

- STR-240 (PR #100) is the user-visible one. A failed Health
  Connect read used to return an empty snapshot, so the dashboard
  rendered a zero-filled health section indistinguishable from a
  day with genuinely no steps, weight, or sleep. The read now
  returns degraded pages and the section renders as unavailable.
  The same PR converts 18 exception-as-control-flow sites to
  value-based parsing, stops the import pipeline from silently
  dropping equipment inference and malformed synthesis
  diagnostics, makes the client-log buffer cancellation
  transparent, and surfaces the three background outcomes that
  used to be discarded (insights and the weekly series no longer
  go silently stale after a finalize or edit).
- STR-237 (PR #98) removes logging capability from the domain
  and application layers entirely: no logging port, logger type,
  or log call exists in those source sets, and build gates fail
  if one appears. Operational-failure diagnostics ride the
  sealed outcome branches as values and are recorded once at
  presentation boundary components. Health snapshot read
  failures carry their cause on the diagnostic and are drained
  once at the dashboard.
- STR-238 (PR #99) ends log-and-return-failure in the data
  layer. 20 of 24 propagate-path sites are converted so each
  failure is recorded exactly once at the invoking boundary;
  the worst chain previously recorded a single pull failure
  four times. The three interim exceptions the ticket named
  were closed by STR-240; one permanent exception remains by
  design (the anti-feedback-loop breadcrumb).
- STR-243 (PR #97) replaces raw `Throwable` `Result` failure
  payloads with per-area sealed outcome types across roughly
  195 producer sites in 10 clusters. Ports return outcomes
  instead of throwing typed exceptions across the boundary,
  and the Google sign-in failure classification is
  single-sourced in one classification type used everywhere.
- STR-241 (PR #95) returns expected failures as typed sealed
  outcomes instead of throwing domain exceptions that were
  caught one layer up.
- STR-239 (PR #94) makes the `runCatching` wraps in suspend
  code cancellation-transparent, so coroutine cancellation is
  no longer absorbed as an ordinary failure, and fixes the
  discarded-result sites (auth compensation, import rollback)
  that hid failures entirely.

## Source PRs

- #95 refactor(errors): return expected failures as typed outcomes instead of throws (STR-241)
- #97 refactor(errors): replace raw Throwable Result payloads with sealed outcomes (STR-243)
